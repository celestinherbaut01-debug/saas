# ProspectFlow — V4 implementation and validation

This change starts from remote commit `7146675d8b69272856413d013ace17f674d20cc9`. It preserves the existing Command Center and CRM conversion entry points. No `.env.local` or real key was read or edited.

## Product changes

- Connected product: a midnight blue canvas, lavender/turquoise identity, module-specific mastheads, open editorial sections, redesigned KPI tiles and tables, responsive workflow lanes, accessible focus states, and reduced-motion support. Existing forms, drawers and empty states inherit the product tokens. The drawer now traps keyboard focus and restores it when closed.
- Garage: an actual workshop board with upcoming arrivals, diagnosis, quote, validation, parts blockage, intervention, ready and delivered stages. Contextual stage advancement and parts-blockage actions persist through existing mutations. Technicians, pieces, quotes and invoices remain attached to the repair order. A maintenance date is explicitly supplied by the garage and saved on the vehicle; no guessed service interval is used.
- Web agency: a production board groups real projects by production/delivery/maintenance; it shows client, deadlines, completion from actual tasks, declared task blockers and linked domains/services. Tasks can be completed or blocked from that view. Existing project-linked invoicing remains in place.
- Cleaning: a daily operations view shows scheduled interventions, actual employee assignments, uncovered work, incidents, contract renewals and low consumables; interventions can be assigned and completed directly. Quality and incident modules remain connected.
- Restaurant: a kitchen view combines actual low-stock ingredients, supplier ordering, recipes, registered costs and waste. A 35% food-cost reference is labelled as a reference, not a business-specific target. Missing recipe lines/prices remain incomplete. No sales, consumption, real margin or revenue is manufactured.
- Real estate: dedicated owners, properties, mandates, buyers, visits and offers with tenant-scoped relationships, photos, an eight-stage property pipeline and a property dossier that surfaces associated mandates/visits/offers. Owners can reuse an existing CRM-converted client's contact data. Mandate/visit/offer database triggers advance appropriate stages without marking a property sold automatically.
- Property → Studio: `Créer la communication` opens Studio using a tenant-scoped property ID. Saved property fields prefill the form; source fields are read-only until the property is updated. Generation re-reads the stored property server-side. Instagram/Facebook/email/site/SMS are generated by the existing deterministic generator and persisted in the Studio library with a source-property link. Existing property photos are copied into independent creation paths so removing a Studio photo cannot delete the property's source. Copy failures are explicit and creation cleanup is attempted. This is content preparation, not automatic social publishing.
- Command Center: distinct operational facts, priorities, blockers, opportunities and planning. Object references open the corresponding record in existing modules. No fake “mark done” dismissal hides ongoing work. Empty planning means no entries were recorded, not guaranteed available business capacity.
- Continuity: CRM gained → core client uses one RPC transaction/row lock, avoiding the previous insert-then-link race. Clients remain reusable across operations. Studio and NOVA link back to actual properties. Real estate is included in métier resolution, onboarding descriptions, NOVA signals and Business Twin schedule/renewal inputs. The capability registry separates honest generic fallback from actual specialized workflows.
- Pricing: six explicit paid plans at €29/59/39/69/89/129. Annual price is monthly ×10. Outcome, target, limits and upgrade explanations complement existing entitlement-driven feature lists. Complete describes acquisition + operations + continuity. No new payment integration, urgency, reviews, clients or ROI claims were added; paid plan switching is not represented as a working payment flow in production.
- Analytics: real métier stage distribution and persisted Studio counts, including property-originated creations and manually marked published status; no social reach or attributed revenue is implied.
- Data failures: checked tuples and shared loaders reject failed reads rather than replacing them with `[]`. Server pages show distinct permission, missing-schema and network states with retry. True successful empty responses still produce empty states. Mutation failures in dedicated métier owners are visible.
